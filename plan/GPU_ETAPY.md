# Етапи для комп'ютера з відеокартою NVIDIA

Оновлено 28.11.2026. Що запускати на сильнішому комп'ютері, у якому порядку і як повернути результати. Усе за преєстрацією 1.1 (`configs/prereg.md`, розділ 11.1), тож результати можна прямо порівнювати з уже порахованими S6-S7 (`reports/v11_s06_s07.md`).

## Що і чому саме на GPU

| Пріоритет | Етап | Що дає для диплома | На цьому ноутбуці (CPU) | На GPU (орієнтовно) |
|---|---|---|---|---|
| 1 | **S8 за v1.1**: GraphSAGE (повна модель і 6 абляцій), R-GCN і HGT з текстом і без; 5 seed; 20 перестановок | H2 з повною моделлю і co_publication (єдине ребро, що покриває золоті); рядки GNN у таблиці моделей | ~110 с на епоху, разом приблизно 1-1,5 доби | кілька годин (на RTX 3060 було 7-16 с на seed без co_publication; не вимірювалось з ним) |
| 2 | **XLM-R за v1.1**: P1 і P2, 3 seed, 3 епохи; 20 перестановок по 1 епосі | найсильніша текстова модель у сходах моделей; без неї порівняння неповне | нереально | приблизно 2 год основні прогони + 20 перестановок (оцінка: на 6 ГБ до 3-5 год) |
| 3 | Пізніше: S9 гейтований гібрид і абляції | H1 і H2 з найкращою гібридною моделлю | повільно | код ще не написано, підготую після S8 |
| 4 | Пізніше, за бажанням: інші енкодери (mmBERT, multilingual-e5) як заморожені ембединги | чи впирається якість у bge-m3 | нереально | код ще не написано |

Лишаються на цьому ноутбуці: оцінка на золотих (`scripts/v11_eval.py` і майбутня оцінка S8), S10 (каскади), S11, S12, LLM-компаратор через API, текст.

## Кроки

### 1. Код

```bash
git clone https://github.com/Obizonko/Dyplom2026.git
```

Якщо репозиторій там уже є: `git pull`. Перед цим треба запушити поточні коміти з цього ноутбука (зараз вони лише локальні).

### 2. Дані

Потрібен той самий архів `Dyplom2026_data.zip`, що вже був (data/ і logs/). Розпакувати в корінь репозиторію:

```bash
tar -xf Dyplom2026_data.zip -C Dyplom2026
```

Нових великих файлів версія 1.1 не потребує:
- `data_small/corpus_channel_counts.csv` уже в git;
- пари копій `data/interim/features/sem_pairs_any_0985.parquet` скрипт порахує сам (на CPU це ~4 хв, на GPU швидше);
- за бажанням їх можна скопіювати з цього ноутбука (близько 1 МБ), тоді перерахунку не буде.

### 3. Середовище (Windows, CUDA 12.8)

```bash
uv venv --python 3.13 .venv
uv pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
uv pip install -r requirements.txt
uv pip install pyg-lib torch-sparse -f https://data.pyg.org/whl/torch-2.11.0+cu128.html
```

Без uv: `python -m venv .venv` і `.venv\Scripts\python.exe -m pip install ...` з тими самими аргументами. Рядки `hnswlib`, `pyg-lib`, `torch-sparse` у `requirements.txt` на Windows без MSVC можуть не ставитись: hnswlib не потрібен, а pyg-lib ставиться останньою командою.

### 4. Перевірка (кілька хвилин)

```bash
powershell -ExecutionPolicy Bypass -File scripts\gpu_run.ps1 -Stage check
```

Перевіряє CUDA і pyg-lib, наявність даних, рахує ваги пулу і проганяє перенавчання на 32 прикладах для GraphSAGE, R-GCN і HGT плюс самоперевірку XLM-R. Якщо щось падає, повідомлення каже, що саме.

### 5. Запуск

```bash
powershell -ExecutionPolicy Bypass -File scripts\gpu_run.ps1 -Stage s08
```

```bash
powershell -ExecutionPolicy Bypass -File scripts\gpu_run.ps1 -Stage xlmr
```

Або все разом: `-Stage all`.

- Параметри: `-Seeds 5` (GNN), `-XlmrSeeds 3`, `-XlmrPerm 20`, `-BatchSize 32`.
- Для 6 ГБ VRAM ставте `-BatchSize 16`. Для GPU від 12 ГБ можна додати `-Unfreeze` (XLM-R навчає і словникові ембединги; це запишеться в звіт).
- Будь-який етап можна перервати і запустити знову: готові одиниці пропускаються.
- Менше 20 перестановок для XLM-R (`-XlmrPerm 5`) економить кілька годин, але це відхилення від розділу 11.1 п. 6, і його треба буде записати.

### 6. Стежити за прогресом

```bash
.venv\Scripts\python.exe -I scripts\progress_page.py --watch 30
```

Далі відкрити `reports\progress.html` у браузері: сторінка оновлюється сама. На ній картки «S8: GNN (v1.1, GPU)» і «XLM-R (v1.1, GPU)».

### 7. Повернути результати

Найпростіше: на GPU-комп'ютері `git add results/v11 && git commit && git push`, тут `git pull`. Прогнози малі (кілька МБ). Якщо без git: заархівувати папки `results/v11/08_gnn` і `results/v11/06_text` (лише нові файли `xlmr*`) та логи `logs/v11_s08.log`, `logs/v11_xlmr.log`.

Після повернення я рахую метрики на золотих (два бутстрепи, H2 за трьома порогами, перестановочні контролі), пишу звіт S8 і оновлюю `reports/v11_s06_s07.md` рядками XLM-R.

## Що вирішити до запуску

1. Чи запускати P3 для GNN (5 груп каналів × 5 seed, приблизно у 5 разів довше). Пропоную спершу лише P1, бо H2 за преєстрацією стосується P1.
2. XLM-R: 20 перестановок, як вимагає преєстрація, чи менше з записом відхилення.
